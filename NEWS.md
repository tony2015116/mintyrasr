# mintyrasr 0.5.2

Found with real ASReml-R 4.2.0.481 (pedigree BLUP crashed R):

* **Crash fixed.** ASReml-R 4.2 aborts R (exit code 1033) when an `ainverse()`
  matrix (class `ginv`) is the `vm()` source under the name `ginv` in a formula
  built inside a function. Inside the model the matrix is now called
  `relmat`: components read `vm(id, relmat)`. In `random` you can still write
  `vm(dam, ginv)`; output names such as `prop_vm_dam_ginv` are unchanged.
* `workspace = "auto"` (new default, was `"30Gb"`): sized from individuals x
  traits. ASReml reserves the whole workspace for every fit: with 30Gb one
  fit took 31 s instead of 3-6 s, and it can exhaust the memory of a 32 GB
  computer.
* `ainverse()` results (class `ginv`, no `INVERSE` attribute) are recognised
  as inverses without a warning.

# mintyrasr 0.5.0

## Pedigree, genomic and single-step

* `ginv` takes any inverse relationship matrix: A^-1 (`ainverse()`), G^-1 or
  H^-1. `dense = "auto"` (new default) puts the term in `dense` only for a
  (nearly) full inverse, not for a sparse A^-1. With `ainverse()` and
  `inbreeding = NULL`, F is taken from its `inbreeding` attribute.
* New `asr_compare()`: the same scenarios with several matrices (e.g. ABLUP,
  GBLUP, ssGBLUP) on the same folds, stacked with a `method` column.

## Other models

* Only `vm(<id>, ginv)` itself is the direct genetic term, so `vm(dam, ginv)`
  (maternal genetic) and `vm(id, ginv):herd` (G x E) can be added in `random`.
* Every extra random term is reported as `prop_<term>` (its share of the
  phenotypic variance, e.g. c^2, pe^2, m^2); `rep` (repeatability) with
  `ide(<id>)`; `rB_<X>` (type-B genetic correlation) with `vm(<id>, ginv):X`.

## Parameters only

* `cv = NULL` (new default): genetic parameters without cross-validation, e.g.
  for every group of `w2l_nest(by = )` or every trait pair of `c2p_nest()`.

## Documentation

* New articles (English and Chinese): pedigree, genomic and single-step;
  repeatability, maternal effects and G x E; genetic parameters for each
  group; correlations between traits in each population; the same trait in
  different populations.

# mintyrasr 0.4.0

## Cross-validation without a reliability filter

* `cv_min_rel = -Inf` (new, default): validation individuals are **not**
  filtered by reliability. They have no own record in the training set, so a
  low reliability is expected; a filter kept only well-connected individuals,
  biased PA and shrank the sample. `min_rel` (default 0.05) now applies to the
  final GEBVs of the full-data fit.
* New output `gebv`: GEBV, PEV, F, reliability and `reliable = rel >= min_rel`
  for every individual of each full-data fit (`keep_gebv = TRUE`). Tables over
  Excel's row limit are written to `<path>_<name>.csv`.
* `neg_to_na` now defaults to `FALSE`: dropping negative PA / slopes biased the
  mean upwards. `neg_to_na = TRUE` gives the old behaviour.

## Long runs

* Progress: one line per fit with status, iterations, time and estimated time
  left; a summary line at the end. ASReml's iteration monitor is off while
  mintyrasr runs (`asreml_trace = TRUE` to keep it).
* `max_update` now defaults to 2: a fit that has not converged is continued
  with `update()`; the number used is in `param$updates` / `accuracy$cv_updates`.
* `nonconv = "skip"` (default): a parameter fit that still has not converged
  is reported with `status = "not_converged"` and its CV rows are skipped; a
  CV fit gives `NA` for its fold. `nonconv = "keep"` uses such fits.
* Safe running: errors, non-convergence, boundary estimates and invalid LRTs
  are recorded in the new `$log` (time, stage, label, type, message) instead
  of interrupting the loop; one warning at the end. `param` and `accuracy`
  gain `status`; `summary` uses only rows with `status == "ok"`.

# mintyrasr 0.3.2

From the second validation run with ASReml-R 4.2.0.481:

* An LRT where both models have the same number of free parameters (df = 0,
  e.g. a covariance restrained at a bound) gives `rg_p = NA` with a warning,
  instead of a misleading p = 0.
* New `min_n = 10`: a fold needs at least `min_n` validation individuals with
  a usable GEBV (after `min_rel`) for PA, accuracy and slope. With a low h2
  the reliability filter could leave 2-7 animals and PA / slope were noise.
* `cv_iter` is documented as the length of the iteration history (2 for
  fixed variances).
* Confirmed on real ASReml-R: `rg_p` equals `lrt(full, idh, boundary = FALSE)`;
  fixed-variance CV fits give no warnings; `cv_vc = "warm"` needs about half
  the iterations of `"estimate"` and gives the same results.

# mintyrasr 0.3.1

Fixes found by running the validation script with ASReml-R 4.2.0.481:

* The LRT of rg = 0 (and `test_rp`) uses `lrt()`, the name in ASReml-R 4.2,
  with a fallback to `lrt.asreml()` for older releases. Before, the call
  failed silently and `rg_p` was always `NA`. LRT failures now give a warning.
* Fixed-variance CV fits (`cv_vc = "fixed"`, `maxit = 1`) no longer pass on
  ASReml's expected "Log-likelihood not converged" warnings.
* `accuracy` gains `cv_converge` and `cv_iter` (iterations of each fold's fit).
* Confirmed on real ASReml-R: component names for idv, us, idh/diag, corgh,
  corh and corv, `vparameters` order, coefficient names, and h2 / rg / rp /
  repeatability identical to hand-written `vpredict()` formulas.

# mintyrasr 0.3.0

* `traits =` names the response column(s) when the nested data do not use
  `value` / `value1` + `value2` (e.g. `traits = c("bfs", "nls")`).
* `asr_scenarios()` runs the `mt_bt` scenario of `cv_scenarios()` (one trait
  treated as a different trait in each of two groups), with a `diag`
  residual and without rp.
* `test_rp = TRUE`: joint LRT of all covariances = 0. `rp = FALSE` drops the
  phenotypic correlation.
* corgh correlation rows such as `...!trait!b:!trait!a.cor` are recognised.

# mintyrasr 0.2.0

* LRT of rg = 0 uses `idh(trait)` and `boundary = FALSE`.
* New columns: `pa` = r(y, GEBV) (the former `accuracy`), `accuracy` =

* `cv_vc = "fixed"` (`maxit = 1`), `"warm"` or `"estimate"`.
* `genetic_cov`, `random_cov`: `us`, `idh` / `diag`, `corh`, `corgh`;
  `random = ~ ide(id)` etc.; `na_x`; `asreml_args`.
